- **07 Q&A question resolved (2026-09-11), from source, not inference:** neither "fusion" nor
  "lost async write". `pregel/loop.js` `tick()` writes step N's checkpoint *after* step N's
  writes are applied; a crash inside the node means step 0 never completed, so no step-0
  checkpoint was ever queued in any durability mode. The `{"__start__": 1}` row is the
  `source: "input"` checkpoint from `_first()`. `durability: "sync"` (index.js:1053) only awaits
  that input write before step 0 starts. The Q&A carries a dated correction note.
- **New work fact from step 5:** same-thread concurrent invokes race — `getTuple` is
  `ORDER BY checkpoint_id DESC LIMIT 1` with no lock → accidental fork, one turn silently lost.
  "Does the API layer serialize per thread_id" is now a must-verify, not a nice-to-know.
- **Work facts learned:** `thread_id` = chat session id (one thread per chat). 30-day retention

## Exercises — scaffolded by Claude Code, written by Snehasis

Each block ends with an exercise built without the teaching file open. To avoid delay,
Claude Code creates the **scaffold** at the end of the block's last teaching session:
file with imports, state annotation, empty node stubs marked `// TODO`, a `main()` that
runs the expected flow, a short checklist of what "done" means at the top, and a `--check`
mode that prints what should be true after a correct run.
Claude Code does **not** fill in node logic, reducers, or mappings, and does not fix
broken exercise code — it asks what Snehasis thinks is wrong first (claude.md rule).

## Session rules

- Something every day, even 15 min. Weekday sessions capped at 30–45 min; no 150-min bursts.
- One file per idea. A second thread ID or a commented-out call in `main()` means it wants
  to be two files. Shared setup goes in a `_*.ts` helper.
- Every session ends with: one Q added to the module's `-qa.md`, one review card pass/miss,
  `npm run focus:log`.
- Build raw before the abstraction (SSE before AG-UI, JSON-RPC before the MCP SDK).
- Q&A claims must match what the tables/output actually showed. "Inferred" is not "confirmed".
